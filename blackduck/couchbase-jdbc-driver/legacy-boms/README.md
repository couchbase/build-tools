# BOMs for pre-flavor JDBC driver releases

Driver releases up to 1.1.1 were published to Maven Central as
`com.couchbase.client:couchbase-jdbc-driver`. Each is a single root Maven
module with no license-automation-plugin, so the scan can't generate a
`bom.txt` from the source the way it does for the flavor builds (1.2.1 and
later). For those releases, `get_additional_source.sh` falls back to the
files here when the build manifest has no `FLAVOR` annotation:

- `<version>.txt` is the release's BOM, one `groupId:artifactId:version` per
  line, with no comments and no blank lines (`create-maven-boms.py` reads it
  as plain colon-separated rows).
- `<version>.commit` is the driver commit the BOM was generated from. The
  scan fails if the manifest checks out any other commit.

## 1.1.1

The commit is `2ab5b780` (tag `v1.1.1`). It was checked against what Central
serves:

- The Central jar's `Impl-Git-Revision` is `2ab5b780`.
- The `-sources.jar` matches the tag's `src/main` file for file.
- The published pom is the shade plugin's dependency-reduced pom. Its
  properties and plugins match the tag's pom, and only the bundled runtime
  dependencies are dropped from it.
- A rebuild of the tag gives the same 23,645 jar entries, and every
  third-party class is byte-identical. Only `MANIFEST.MF` and two driver
  classes differ: build time, and javac's lambda numbering across JDK versions.

The BOM was generated by applying the driver's `main` license setup to the
tag:

1. Copy `src/main/licenses/` from `main` (supplemental models and templates).
2. Add `org.apache.hyracks:license-automation-plugin:0.3.9` to the root pom's
   `<build><plugins>`, configured as on `main` (`bom.ftl`, test/provided
   scopes excluded, the driver itself excluded). Point `templateRootDir` and
   the model path at `${project.basedir}`, since this is the root module.
3. Add the same `extraDependencies` as `main`'s Analytics flavor, for the
   gRPC 1.69.0, protobuf-java 4.29.2 and PerfMark 0.27.0 that core-io shades
   under protostellar. core-io 3.11.1, which 1.1.1 bundles, embeds the same
   versions as 3.12.x.
4. `mvn -DskipTests generate-resources`, then sort `target/bom.txt` and drop
   blank lines.

The result was checked against the Central jar. Every artifact whose
`META-INF/maven` metadata the jar embeds is listed, except the driver itself,
`core-io-deps` and `protostellar`, which are excluded on purpose, as on
`main`.
